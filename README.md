# 社員向けお弁当注文アプリ(リリテイ弁当)

Flask + SQLite で作られた、社内のリリテイお弁当注文を掲示板の丸つけ運用からデジタル化するアプリです。
実際の運用フローに合わせて作られています。

## 実際の運用フローとアプリの対応

| 今までの運用 | アプリでの対応 |
|---|---|
| 金曜9時までに来週分を掲示板に掲示 | 管理者が「メニュー登録」で日付ごとにメニュー名を事前入力(月次でリリテイのPDFから、**PDFアップロードで自動読み取りも可能**) |
| 頼む人が掲示板に丸をつける(締切: 金曜15:00) | 社員がアプリで来週分(月〜金)をまとめて選択して送信。締切は金曜15:00(設定変更可) |
| フライあり・フライなし・野菜の3種類 | この3種類が固定の選択肢。アプリ内では「フライあり/フライなし/やさい」と表示します(「あり/なし」だけだと、別の場所で使っている「注文あり/なし」の意味と紛らわしいため「フライ」を残しています)。日々の具体的な献立名(唐揚げ、焼き魚など)は管理者が月次で登録 |
| 当日弁当チケットを箱に入れ、受け取ったら一覧表にチェック | チケット・箱の運用はこれまで通り紙のまま。アプリ側は、氏名×曜日のマス目になった「受け取りチェック表」を週1枚のA4で印刷でき、紙代を抑えつつこれまで通りレ点をつける運用を継続できます |
| 当日に追加で頼みたい人はメモで申告 | 当日9:00までに松浦さんか陽介さんまでメモで伝える運用です。伝えられた管理者が「当日分の代理注文」から、締切に関係なく代わりに登録可能 |
| 価格300円(会社補助あり、リリテイ店頭価格は600円) | 価格は管理画面の「設定」で管理(初期値300円) |

## 主な機能

- 社員側: 来週分の注文をカレンダー形式でまとめて選択・送信(月〜金を1回の操作で確定)、注文履歴と費用の確認、キャンセル
- 週間の注文状況を一目で確認: 各週の一番上に、紙の掲示板で横一列に丸をつけていたのと同じ感覚で、月〜金の選択状況を色分けした丸印で表示します(フライあり=オレンジ/フライなし=紫/やさい=緑/注文なし=グレーの点線)。文章を読まなくても、色の並びを見るだけでその週の注文状況がぱっと把握できます
- 管理者側: 月次でのメニュー一括登録(日付ごとにフライあり/フライなし/やさいの3項目、**リリテイの月間PDFをアップロードして自動読み取り**、または1日ずつ手入力)、注文一覧、支払い状況(精算済/未精算)の管理、注文締切(曜日・時刻)と価格の自動計算ルールの設定に加えて、週ごとに締切日時を個別に手動設定・上書きする機能、当日分の代理注文(締切後にメモで依頼された分の代理登録)
- 集計サマリー: 日別の食数・区分ごとの内訳を自動集計。リリテイへの発注数の目安として使えます
- 注文忘れ・キャンセル忘れ対策: 社員がアプリを開くと、理由を問わず一番上に「本日・次回営業日の注文状況」が表示されます。管理者側にも「本日の注文 — 朝の出欠チェック用」を用意しており、実際の出社状況と見比べてその場でキャンセルできます(下記「注文忘れ・キャンセル忘れへの対策について」参照)
- お弁当受け取り用のA4印刷チェック表(週1枚): 管理画面の「本日の注文」カードから、氏名を縦・曜日(月〜金)を横に並べたマス目形式のチェック表をA4 1枚で印刷できます。紙の掲示板と同じ「横一列に丸をつける」形なので、毎日印刷しなくても週の頭に1枚印刷しておけば足ります。注文した区分は色付きのラベル(フライあり=オレンジ/フライなし=紫/やさい=緑)に「フライ有り/なし/野菜」の文字を添えて示され、その隣に受け取り確認用のチェック欄があります。白黒印刷でも区分が文字で判別できるようにしています。締切後に当日追加で頼んだ人がいた場合は、その人の行・その日の欄(または、まだ表にいない人なら一番下の空欄行)に丸印を手書きで書き足すだけで対応できます。特定の1日分だけを印刷したい場合のリンクも用意しています

## PDFからのメニュー自動読み込みについて

管理画面の「メニュー登録」から、リリテイの月間PDF(例:「2608-higawari-HP.pdf」のような月次メニュー表)をそのままアップロードできます。日付・フライあり/フライなし/やさいそれぞれの献立名を自動で読み取り、**登録前に必ず内容を確認・修正できる画面**を挟みます。読み取り結果がそのまま自動でデータベースに保存されることはありません。

この読み取り機能は、実際にリリテイの2026年8月分PDFを使って開発・検証しており、お盆休みのような「お弁当がない週」も正しく空欄として扱われることを確認済みです。ただし、リリテイ側がPDFのレイアウト(表のデザインなど)を大きく変更した場合は正しく読み取れなくなる可能性があります。その場合は読み取り結果の確認画面でおかしい箇所に気づけるはずですが、もし毎月うまく読み取れなくなった場合は、`menu_pdf_parser.py` の調整が必要になるか、「1日ずつ手入力」の方でご対応ください。

## 注文忘れ・キャンセル忘れへの対策について

紙の掲示板運用でもあった「注文し忘れ」「休みなのにキャンセルし忘れ」というリスクに対して、外部サービス(メール・LINEなど)を使わずアプリ内だけで完結する形で以下の工夫を入れています。

- 社員がアプリを開くと、何をしに来た場合でも一番上に「あなたの注文状況」が表示され、本日・次回営業日について、注文済みなら内容を、未注文なら「注文なし」を色分けして表示します。本日分が未注文の場合は「休みなどで変更が必要な場合は当日9:00までに松浦さんか陽介さんまでメモで」という案内も出ます。
- 管理画面の一番上に「本日の注文 — 朝の出欠チェック用」を用意しており、実際に出社している人と本日の注文者一覧を見比べて、休みなのに注文が残っている人がいたら、その場で1クリックでキャンセルできます。

これらはあくまで「気づきやすくする」工夫であり、社員が一度もアプリを開かなければ気づけません。より確実に本人へ知らせたい場合は、メールやLINE等での能動的なリマインド送信も追加できますが、社内の連絡手段の情報が別途必要になり、実装の手間も増えるため、今回は見送っています。必要になったら教えてください。

## 週間の注文状況の見える化について

紙の掲示板運用では、1週間分の丸つけ結果を横一列に並べて見ることで、その週の注文状況を一目で把握していました。アプリの社員用画面でもこれを再現しており、各週のカードの上部に月〜金の5日分を横並びの丸印で表示します。

- オレンジの丸 = フライあり
- 紫の丸 = フライなし
- 緑の丸 = やさい
- グレーの点線の丸 = 注文なし

本日にあたる日は背景を薄いオレンジ色にして目立たせています。この表示は締切前・締切後どちらの週でも表示され、下にある選択フォーム(締切前)や選択済み一覧(締切後)を読まなくても、色の並びだけでその週の注文状況を確認できます。

## 注文の締切について

ある週(月〜金)の注文は、**その前の週の指定曜日・時刻**が締切です。初期設定は「金曜15:00」なので、来週分の注文は今週の金曜15:00までとなります。締切を過ぎるとその週の自己申告での新規注文・変更・キャンセルはできなくなります。

これは自動計算の基本ルールで、祝日などで特定の週だけ締切を変えたい場合は、管理画面の「週ごとの締切(手動設定)」からその週だけ個別の日時に上書きできます。メニューを登録したタイミングで、あわせて確認・設定しておくのがおすすめです。上書きしていない週は、引き続き自動計算(前の週の指定曜日・時刻)が使われます。

当日分を追加・変更したい人は、当日9:00までに松浦さんか陽介さんへメモで伝える運用です。管理者は「当日分の代理注文」フォームから、締切に関係なくいつでも登録できます。

締切の曜日・時刻や価格は、管理画面の「設定」からいつでも変更できます。

## 動作環境

- Python 3.9 以上
- 依存パッケージ: Flask (requirements.txt に記載)

## セットアップ

```bash
cd bento-app
pip install -r requirements.txt
```

## 起動方法(お試し・開発用)

```bash
python3 app.py
```

初回起動時にデータベースファイル `bento.db` が自動的に作成されます。
ブラウザで `http://localhost:5000/` にアクセスすると社員用の注文画面、
`http://localhost:5000/admin` にアクセスすると管理画面が開きます。

管理画面の初期パスワードは `admin123` です。**必ず変更してください**(下記参照)。

### 2回目以降、確認するたびに毎回コマンドを打つのが面倒な場合(Windows)

このフォルダに入っている `start_app.bat` をダブルクリックするだけで、サーバー起動とブラウザを開く操作をまとめて行えます。最初の `pip install -r requirements.txt`(依存パッケージのインストール)は一度やれば十分で、2回目以降は不要です。

1. `start_app.bat` をダブルクリック
2. 黒い画面(コマンドプロンプト)が開き、少し待つと自動でブラウザが開きます
3. 確認が終わったら、その黒い画面を閉じればサーバーも止まります(閉じずに次のアクセスを続けても構いません)

## 使い方(管理者)

1. 毎月、リリテイの「日替わり弁当」PDFが届いたら、管理画面の「メニュー登録」で日付ごとにフライあり・フライなし・やさいの3つの献立名を入力します。1件登録すると、次の入力欄の日付が自動的に翌営業日にセットされるので、続けて入力しやすくなっています。あわせて「週ごとの締切(手動設定)」で、その週の締切が自動計算どおりでよいか確認し、祝日などで変える必要があれば手動で設定しておきます。
2. 社員・パートさんは、締切(初期設定: 金曜15:00、週ごとに手動設定した場合はその日時)までにアプリから来週分をまとめて注文します。
3. 締切後、管理画面の「集計サマリー」で日ごとの食数・区分内訳を確認し、リリテイへの注文数の目安として使ってください。
4. 当日、松浦さんか陽介さんが9:00までにメモで追加を頼まれたら「当日分の代理注文」から登録します。
5. 週の頭に、管理画面の「本日の注文」カードから「今週分をまとめてA4で印刷(1枚)」を開いて印刷しておきます。お弁当受け取り時のチェックは、これまで通りこの紙にレ点をつける形で行います。締切後に当日追加で頼んだ人がいれば、その紙に直接手書きで書き足せば足ります(必要なら「当日分だけ印刷」で1日分だけ再印刷することもできます)。
6. 代金が精算されたら、「注文一覧」の支払ボタンを押して「精算済」に切り替えます。

## 社内で継続利用する場合の注意

このアプリは検証用のプロトタイプとして作られています。実際に社内で日常的に使う場合は、以下の対応をおすすめします。

1. **パスワードと秘密鍵の変更**
   環境変数で管理者パスワードとセッション用の秘密鍵を設定してください。デフォルト値のまま使うのは避けてください。

   ```bash
   export BENTO_ADMIN_PASSWORD="好きなパスワードに変更"
   export BENTO_SECRET_KEY="ランダムな長い文字列に変更"
   ```

2. **サーバーへの配置**
   このコードはあなたのPCやCowork環境から取り出して、社内のサーバーやcrowd(Cloud Run、Renderなど)、社内で動かせるPC等に配置して常時起動させる必要があります。デバッグモード(エラー時に詳細なPythonコンソールが誰でも見られる状態)は初期状態でオフになっています。開発中に一時的にオンにしたい場合だけ `BENTO_DEBUG=1` を設定してください。本番運用では絶対に設定しないでください。

   本番運用では `python3 app.py` の直接起動ではなく、`gunicorn` などのWSGIサーバーを使うことをおすすめします。

   ```bash
   pip install gunicorn
   gunicorn -w 2 -b 0.0.0.0:5000 app:app
   ```

3. **社員の本人確認**
   現在は名前を自己申告するだけの簡易ログインです。なりすまし防止が必要な場合は、社内SSOとの連携や、社員ごとのID/パスワード方式への変更を検討してください。

4. **バックアップ**
   データは `bento.db` という1つのSQLiteファイルに保存されます。定期的にバックアップを取ることをおすすめします。

## スマートフォン対応について

全画面レスポンシブ対応済みです。社員用の注文画面はスマホでも見やすいカード形式で表示され、管理画面の一覧表も、画面幅が狭い場合は自動的にカード形式のレイアウトに切り替わり、ボタンが画面外に隠れることはありません。PCの広い画面では通常の表形式で表示されます。

## カスタマイズのヒント

- フライあり/フライなし/やさいの3区分は `app.py` の `CATEGORY_CODES` / `CATEGORY_LABELS`(表示名)/ `CATEGORY_SHORT`(週間印刷チェック表でのラベル文字。白黒印刷でも判別できるよう「フライ有り/なし/野菜」)で定義されています。区分を増減したい場合はここを編集してください。
- 支払い管理は「精算済/未精算」のフラグのみのシンプルな仕組みです。実際の集金方法(給与天引き、現金回収など)に応じて運用してください。
